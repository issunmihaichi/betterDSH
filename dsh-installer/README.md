# dsh-installer — betterDSH 安装向导

一个独立的 DSH bundle，在原生「插件 → dsh-installer → 配置详情」中引导安装本仓的五个插件。
不再注册独立的设置导航入口；向导作为本插件的配置面板，通过官方 `plugins.bundle.config` keyed 槽位挂载。

支持引导安装：

- 用量统计 `dsh-usage-report`
- 账号池 `dsh-account-pool`
- 上下文窗口 `dsh-context-window`
- GitHub 管理 `dsh-github`
- MCP 与技能 `dsh-mcp-skills`

## 首次安装向导

向导本身必须先通过 DSH 自带插件管理器安装一次，之后即可在图形界面选择其余插件。

1. 将 `ISSunmihaichi/betterDSH` 仓库克隆或下载解压到本地可信目录。
2. 打开 DSH 自带的插件管理页，安装该目录中的 `dsh-installer`，使用**绝对路径**，并启用。
3. 如管理器提示需要重启，请重启 DSH；刷新 GUI 后，在原生「插件」页面点击 `dsh-installer` 插件卡片，进入其配置详情即可使用向导。

例如向官方 `plugin_manager install_bundle` 工具传入：

```text
target = "D:/path/to/betterDSH/dsh-installer"
```

这只是示例路径，请替换为你实际克隆的位置。向导没有 npm 发布，不能假设输入包名就能从 registry 下载。

## 使用流程

1. **检查仓库**：输入本地 betterDSH 仓库根目录的绝对路径（不是某一个插件目录）。以本仓目录安装向导时会尝试默认定位到同级插件；若安装管理器复制了向导，请手动填写原仓库目录。
2. **选择插件**：显示源码版本、已安装版本、已启用状态、源码缺失与配置异常。可勾选插件或选择全部未启用且可安装的插件。
3. **预览计划**：计划列出「安装并启用」「启用已安装插件」「跳过已启用插件」。预览不会修改 profile。
4. **确认安装**：只有确认按钮才会调用官方 `pluginManager` 服务。按顺序安装，页面显示当前插件与逐项结果。
5. **完成配置**：根据管理器结果手动重启 DSH或刷新 GUI。账号池账号、GitHub 令牌等由用户到对应设置页自行配置。

## 安全边界与行为

- 仅允许固定五个插件名称；不接受任意 shell 命令或任意包 spec。
- 仓库路径必须是绝对路径。安装前检查包名、版本与 bundle 声明，解析真实目录并拒绝逃逸出仓库的符号链接。
- **仅安装可信源码。** 包名检查不是源码审计或签名认证；官方管理器可能下载 npm 依赖和加载插件代码。
- 使用 DSH 官方 `listBundles`、`installBundle` 和 `setBundleEnabled`，不手写 profile 或自行启动 pnpm。
- 不批准依赖构建脚本、不设置兼容性豁免、不读取或回传凭据。
- 安装计划有效期 5 分钟，确认后一次性消费；安装前再次核对路径和版本。
- 同时仅允许一个安装批次。某项失败后停止后续安装，**已成功项不会整批回滚**；单项回滚由官方管理器负责。
- 现有插件只启用或跳过，**不会覆盖安装或自动更新已有插件**，避免将正在使用的本地开发目录换掉。
- 关闭页面不会取消正在执行的批次；重新打开仍可查询本宿主进程中的结果。结果仅存在内存，重启后以真实安装状态为准。
- 不自动下载 GitHub 仓库、不自动重启 DSH、不提供卸载功能。
- 所有接口挂在 DSH 认证的 `/api` 通道；浏览器仅收到概要与错误代码，原始 pnpm 输出不会回传。

## 技术结构

- `lib/catalog.js`：固定插件目录、计划动作判定和公开错误代码白名单。
- `lib/host.js`：源码检查、确认计划、串行任务和四个 Fetch 路由。
- `lib/client.js`：无需构建的 ModuleLoader 客户端，注册 `plugins.bundle.config`，key 为 `dsh-installer`。
- `cordis.patch.yml`：可移植包名入口。

Host 显式注入 `connection` 与 `pluginManager`；Client 注入 `slots` 与 `locale`。

页面当前主要使用中文，不添加自己的设置导航。状态是 profile 安装/启用选择，不等同于每个宿主 fiber 都已经成功运行；遇到加载问题请查看 DSH 官方插件管理页。
