# betterDSH UX 设计与验收基线

本文是六个插件的交互约定，不是“所有 UX 已完美”的声明。实现保留 DSH 的原生扩展槽位与手写客户端 bundle；本轮不修改运行中的 profile、不发布远程。

## 1. 共用交互原则

### 信息层级

每页先回答：**这是什么 → 当前状态是什么 → 可以做什么 → 结果是什么 → 下一步是什么**。
设置页只承担该插件的业务配置；安装向导嵌在自己的原生插件详情中，不新增设置导航。
上下文面板是会话中的轻量诊断层，不承担 MCP/技能编辑。

### 读取与写入状态

| 状态 | 反馈 | 允许操作 | 禁止行为 |
| --- | --- | --- | --- |
| 首次读取 | 明确加载文案/状态 | 导航离开、必要时切换查询 | 显示貌似可信的零值 |
| 刷新中 | 保留同一数据来源的上次结果，标更新中 | 不受刷新影响的编辑 | 重复请求、用新范围标旧数据 |
| 刷新失败 | 标注旧结果、保留草稿、给重试 | 重试、复制/查看旧结果 | 清空账号输入或自动重开已关闭弹层 |
| 保存中 | 禁止相同操作重复提交 | 按实际流程保留草稿 | 把按钮禁用当作唯一互斥锁 |
| 保存失败 | 明确未保存或可能部分完成 | 检查当前状态后重试 | 将 Promise resolve 等同于成功 |
| 成功 | 明确已保存/已应用/需重启 | 下一步配置 | 自动重启或隐含批准构建 |
| 部分统计/部分安装 | 可见覆盖范围与未完成项 | 缩小查询或续办 | 声称完整结果、伪称整批回滚 |

异步响应必须绑定查询、对象或组件生命周期。较晚返回的旧请求不得覆盖较新的选择。
所有写操作以 Host 返回的持久化/官方管理器结果为准，不以 UI 乐观反馈伪造成功。

### 可访问性

- 使用原生 button、input、label；可点击元素应有可读名称。
- 开关应有 `role=switch`、`aria-checked` 与所属对象的名称。
- 局部等待用 `status`，错误用 `alert`；不让每次后台轮询都打断阅读。
- 对话框需要名称、Escape、焦点边界与关闭后的焦点恢复；只有真实测试完成才能声称符合。
- 图表提供精确语义表，不把重要数值仅放在鼠标悬停提示。
- 一般宽度下不依赖固定大画布；长 token、仓库名、工具名允许换行或横向滚动。

### 安全与恢复

不将密钥、完整命令行中的凭据或原始包管理器日志展示到浏览器。
脱敏必须覆盖 env token、API header、URL userinfo/query 和 CLI 参数；`***` 占位符回传只能恢复对应敏感字段的原值。
安装、克隆等动作的确认需要绑定当时展示的计划，不允许目标目录变更后静默执行旧确认。

## 2. 逐插件设计

### 用量统计

**主任务：**选择时间范围 → 了解输入/输出趋势 → 查看精确日数据。

- 选择器明确选中范围；切换时不展示标错范围的旧图表。
- 刷新显式绕过 Host TTL 缓存，仍共享单飞统计；一个浏览器请求取消不影响其他调用者。
- 刷新失败保留同范围上次成功结果，提供重试；首屏失败也能重试。
- 跳过与未扫描会话数量可见；全部读取失败与“真的没有记录”区分。
- 趋势图旁提供可展开的精确数据表，包含日期、输入、输出和回复次数。

**已知边界：**本机真实会话日志与投影缓存存在已记录的不一致，不将离线测试通过等同于真实对账全部通过。

### 账号池

**主任务：**建立账号/分组 → 配置路由 → 检查状态与额度 → 安全恢复失败。

- 刷新不卸载已有表单，失败时保留最后成功页面与输入草稿。
- OAuth 目录的加载、失败、重试与“没有提供商”分开。
- 同一表单操作使用同步互斥，离开后不再执行已过期页面回调。
- 管理操作的持久化失败返回明确失败；后台用量等 best-effort 写入不应污染无关保存结果。
- 持久化失败可能已经改变内存或部分介质：明确警告未保证持久化，不伪称事务回滚。

- 账号主保存明确成功后记录 canonical ID 与每个优先级的确认结果；相同草稿重试只续未完成项，改主字段只能更新既有 ID。旧编辑器的请求不能关闭新编辑器。
- 分组页与提供商卡复用命名删除确认；第一次点击不写入，可取消/Escape，明确确认才提交目标 ID。

**后续重点：**阶段账本仅当前编辑器内存，不跨刷新保存；主保存结果不明需核对而非自动重放。仍需服务端事务与密集账号表的键盘/窄窗口实机验收。

### 上下文窗口

**主任务：**打开占用面板 → 读分类与具体工具 → 返回会话。

- 保留当前实现的平铺 `server · tool` 工具明细，不依据旧说明恢复两级树。
- Client 读取单飞/清理，新会话不显示旧分类；Host 缓存默认 5 秒 TTL/128 条 LRU，同会话请求单飞，取消订阅互不影响，dispose 防止迟到回填。
- 请求失败或使用旧结果需可见，不将 stale 结果伪装成刚更新。
- 弹层位置在视窗内，Escape/焦点处理不影响正常输入工作流。

**后续重点：**触屏、屏幕阅读器、缩放和不同宿主布局的实机组合验收。

### GitHub 管理

**主任务：**连接 → 选择仓库 → 核对克隆计划 → 执行并查看任务结果。

- 设置写入串行合并，后台刷新不覆盖未保存草稿。
- 远程仓库列表/分页、计划与工具结果绑定请求世代；旧结果不覆盖新查询或新选择。
- 确认必须匹配展示的仓库、URL、目标目录、分支与深度；计划变更后要求重新确认。
- 任务轮询单飞；网络错误或 unknown-job 不永远表现为“下载中”，给可恢复状态。
- HTTP 失败必须检查；自动保存失败有局部可见反馈。

**后续重点：**完整令牌换号身份失效、仓库截断提示、焦点转移和 segmented radio 键盘规范。

### MCP 与技能

**主任务：**查看服务/技能 → 启停 → 安全编辑配置或查看技能正文。

- 配置请求体只解析一次；非法 JSON 返回输入错误，不当内部错误。
- 配置与 endpoint 统一脱敏；普通非敏感字段中的 `***` 不被任意还原。
- 开关有名称与状态；对话框内直接显示验证与保存错误，不藏到遮罩后。
- 他插件拥有的配置需明确二次确认；内容变化后原确认失效。

**后续重点：**基于配置版本的冲突检测，避免外部写入被旧编辑器覆盖；已补模态 Tab/Escape/焦点恢复的接口模拟，仍需真实浏览器与屏幕阅读器验收。

### 安装向导

**主任务：**检查本地来源 → 勾选 → 预览 → 确认 → 处理结果。

- 挂在「插件 → dsh-installer → 配置详情」，不恢复旧设置入口。
- 空选择、缺失源码、异常已安装 bundle、计划过期分别给明确下一步。
- 只安装固定目录；已有插件只启用或跳过，不覆盖开发安装。
- 错误映射到可信公开代码和恢复文案；依赖构建、版本不兼容等交给原生管理器处理。
- 显示已处理/总数；失败停批，已成功项保留，未开始项不会伪标失败。

**后续重点：**与原生管理器任务事件整合、可信远程来源及升级规划；未经签名检查不能声称源码可信。

## 3. 验收层级

1. **离线契约**：真实 Request/Response、deferred Promise、持久化拒绝、组件生命周期与树语义。
2. **打包契约**：主入口、白名单、相对模块依赖、账号池 source/runtime 快照一致。
3. **实机交互**：窄/宽屏、明暗主题、纯键盘、Escape/焦点、长文本、真实断网/恢复。
4. **运行验收**：当前 GUI 安装后刷新/重启，确保不是在另一个 server 上验证。

本轮主要完成第 1–2 层；不将模拟 React 树测试宣传为第 3–4 层已完成。每次回归应记录具体范围和残余事项。

## 4. 后续风险清单（未承诺本轮全部消除）

| 优先级 | 范围 | 剩余边界 | 验收要求 |
| --- | --- | --- | --- |
| 高 | MCP 配置 | 他插件/外部写入与旧编辑器的整体替换存在冲突；刷新与修改仍可能竞争 | 基于配置版本的 compare-and-set，迟到刷新不得覆盖修改结果 |
| 高 | 账号池 | 多请求保存/凭据/运行内存不具备全局事务；OAuth start/finish/轮询生命周期仍需统一 | 保存阶段明确、可恢复；关闭后不得自动打开授权页；慢轮询不重叠 |
| 中 | GitHub | token/MCP/设置非全局事务，任务跨页/重启恢复与取消未支持 | 明确部分完成；重试不重复克隆；失效任务可恢复或转人工 |
| 中 | 上下文 | 同时不同会话的 inflight 尚未排队限流；旧读取 API 不一定真取消 | 大量不同会话请求有界；dispose 不泄露订阅/观察对象 |
| 中 | 用量 | 真实日志与投影缓存的六条差异；共享统计暂无 dispose 取消 | 固定日志复现差异；保留已知口径，不以零值掩盖失败 |
| 中 | 全部页面 | 本轮无真实浏览器、缩放、触屏、主题与屏幕阅读器验收 | 逐页键盘/焦点/窄屏/长内容测试，并保存新版真实截图 |

该清单用于继续维护，不代表相关操作永远安全，也不把离线模拟替代成真实 UI 验收。
