## 实施验证方式

- 真正的 `Request` / `Response` 用于保存与路由契约，不能重复消费的 body 未被 fake 掩盖。
- deferred 与可控计时器用于反序响应、先提交后切编辑器、重复点击和轮询不重叠。
- 操作级持久化账本保留已经失败的 promise；立即/延迟拒绝、并发不同操作和无关后台用量失败都做了回归。
- Client 测试为轻量 React hook/tree 与 DOM 接口模拟。开关、表格、状态行和弹层语义可检验，但不等同于真实浏览器焦点/布局或屏幕阅读器验收。
- 全部离线测试不写 live profile、不读取真实凭据、不执行真实 git 克隆、不访问供应商。HTTP/WebSocket 测试仅启动临时本机 fixture server。

## 打包验收

使用 [打包工具](../tools/package-release.py)重新生成六个当前版本 `.tgz`，并建立合集 ZIP。核对的是：

1. 运行文件与仓库源文件逐字节一致；`package.json` 允许 pnpm 重排字段，但完整 JSON 语义必须一致。
2. 主入口、bundle patch、所有 exports 及相对 imports 全部存在；路径不逃逸，无符号链接、依赖、refs 或 Git 元数据。
3. 所有 patch 的加载入口可移植，包内身份与版本与源清单一致。
4. 合集只选六个**当前版本**，不会把输出目录里旧 tgz 一并收进去。
5. ZIP 含 tgz、已展开运行目录、安装说明、UX 文档与 SHA256；CRC 和每个展开文件均与已验证 tgz 一致。

SHA256 只用于完整性核对，不是信任签名、第三方安全审计或源码可信认证。运行目录不带源码测试 tools；维护与回归请使用仓库。
